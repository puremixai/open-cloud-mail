# 前后端优化交付与验证

分支：`codex/frontend-backend-optimization`。本次保留 Vue/Pinia、Hono/D1/KV/R2 技术栈，修改邮件数据加载、下载权限、会话隔离与邮件处理的一致性。

## 已实现

- 收件箱、已发送、星标及管理员列表只取摘要；打开、回复、转发时请求授权详情。详情缓存按身份隔离，最多 30 封、有效期 5 分钟；并发请求去重，旧请求不能覆盖新会话。
- 翻页可跳过重复 COUNT，刷新列表与后台轮询支持取消。初始化、正文加载失败可重试；退出及 401 清除邮件和编辑器内存状态。
- DOMPurify 清理正文 HTML，限制内联 CSS，保留常见表格排版。默认阻止外部图片，用户选择加载后才请求；切换邮件重置选择。
- 普通详情验证邮件归属，管理员详情验证权限。附件使用 15 分钟签名链接；下载路由限制对象命名空间，禁止读取 KV 配置与原始邮件。上传的 HTML/SVG 强制下载并设置隔离响应头。
- 修复多设备退出的异步 token 读取、会话 TTL 和权限路由前缀匹配。
- 发送使用持久化幂等键、D1 原子额度预留和统计。确认未发送返回 424，可手动重试；不确定结果保留同一个键，禁止自动重复发送。
- 收信保留原始字节与处理状态；附件写入失败可由定时任务恢复。邮件、附件引用及星标按固定批次删除，对象删除失败进入持久化重试队列。
- 增加前端测试与 PR/分支 CI；部署工作流先运行两端测试。后端 `test` 改为测试，原测试环境部署命令改为 `deploy:test`。

## 验证范围

测试使用本地 SQLite、模拟 D1 事务、存储及邮件服务，不连接生产邮箱或云数据。

- 后端完整单元测试：16 个文件、130 项通过；包括 37 项发送/接收一致性测试和 4 项部署前迁移测试。
- 前端完整单元测试：13 个文件、108 项通过；包括真实组件/Pinia、跨页面星标竞态、附件过期刷新和正文安全测试。
- Vite release 生产构建通过；Worker `wrangler deploy --dry-run` 打包通过（4074.26 KiB，gzip 739.68 KiB），没有部署。
- 真实浏览器加载生产构建配合本地模拟 API：首屏只请求一次 `full=0` 列表，点击邮件后才请求详情，再次打开命中缓存；返回列表后未读标记为 0，退出后返回登录页，未出现控制台异常。
- 真实浏览器正文组件检查：点击前外部图片请求数为 0，点击后为 1；切换邮件后重新要求选择，注入的脚本未执行。
- Wrangler 本地 D1 实跑部署前脚本：空数据库返回 `new-database`，模拟旧库升级返回 `migrated`，再次执行返回 `current`；版本为 1，原有已用额度 7 保持不变。

构建仍有约 556 kB（gzip 188 kB）的最大 JavaScript 分块和约 316 kB（gzip 118 kB）的入口分块，未声称包体积降低。构建提示大型分块及 Browserslist 数据较旧；编辑器进一步延迟加载和依赖拆包可另行优化。本次没有生产负载或网络延迟压测。

## 上线前必须处理

1. 部署工作流已在激活新版 Worker **之前**运行 `node scripts/migrate-mail-operations.mjs --remote --config wrangler-action.toml`，迁移现有数据库。手动部署也必须先运行该命令并换成自己的 Wrangler 配置；先用 `--local` 验证本地环境。脚本只做新增表、列和索引，逐步执行、最后记录版本；中途失败会阻止部署，重新运行会检查已有列并继续。
2. 确认 `mail_schema_version` 存在版本 1。全新空数据库仍由现有初始化入口 `/api/init/:secret` 建表，并运行相同迁移；新实例初始化成功后才能接入业务流量。保管好密钥，不把含密钥的 URL 放入日志或文档。具体新表、字段及恢复语义见 [后端说明](2026-09-05-mail-reliability-handoff.md)。
3. 若 R2/S3 桶或 CDN 仍允许公开直读附件，需要在存储/CDN 配置中关闭该入口；应用的签名校验不能撤销另一个公共域名已有的访问能力。历史公开附件 URL 应失效或清理对应 CDN 缓存。
4. 旧 API 客户端应使用详情接口获取签名附件链接，并在发送重试中复用 `requestId` 或 `Idempotency-Key`。省略幂等键的旧客户端仍可发送，但跨请求去重没有保证。

## 保留的恢复边界

- `dispatching` / `uncertain` 发送及进程中断留下的 `preparing` 发送需要结合服务商记录人工核对，定时任务不会盲目重发。
- 定时恢复收件只恢复本地邮件，不补发 Telegram 通知或外部自动转发；原始邮件尚未成功归档时仍依赖上游重投。
- 历史没有操作记录和原始归档的 SAVING 邮件不会被直接改成成功；应人工检查。新 D1 日统计不回填历史 KV 日计数。
- 回滚代码时保留新增表与字段，尤其不要删除幂等记录；回滚旧公开下载代码会重新开放旧风险。

本次仅在本地分支完成实现和验证，没有推送、合并或部署。
